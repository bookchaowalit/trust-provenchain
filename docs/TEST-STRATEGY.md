# Test Strategy

**Current gate:** local compilation and deterministic behavior

## Local checks

```bash
npm test
npm run typecheck
npm run compile
```

The test suite covers deterministic SHA-256 hashing, changed-byte detection,
hash validation, Solidity compilation, ABI surface, and non-empty bytecode.

`tests/notary-registry-evm.test.mjs` deploys the compiled bytecode into an
in-process EVM (`@ethereumjs/evm`; no network, RPC or key) and checks the
contract behaviour: unknown-hash read-back, first registration (submitter,
block timestamp, `DocumentNotarized` event topics and data), duplicate
registration (`AlreadyNotarized` revert, first record kept), zero hash
(`EmptyDocumentHash` revert), independent hashes, and that sending ether
reverts. Removing either revert from the contract makes these tests fail.

`npm run typecheck` runs `tsc --noEmit` with `strict` + `checkJs` over
`src/`, `scripts/` and `tests/` (types are JSDoc annotations in the `.mjs`
files). CI runs lint (none yet), typecheck and tests through the shared
`platform-ci-workflows` Node job.

## Required before testnet

- Done: in-process EVM tests for zero hash, first registration, duplicate
  registration, event fields, and read-back behavior.
- Add fuzz/property tests for arbitrary non-zero `bytes32` values.
- Run a Solidity static analyzer and manually review the generated bytecode/
  ABI against the source.
- Execute one bounded testnet transaction with a sample non-sensitive fixture.
- Record transaction hash, chain ID, contract address, compiler version, and
  verification result without recording the fixture contents.

## Required before production

Legal/privacy acceptance, a customer pilot, operational monitoring, recovery
documentation, and a separately approved release decision are mandatory.
